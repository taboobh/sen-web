# sen-web：特教通報網前端原型

React + Vite + TypeScript + Ant Design，後端以瀏覽器內的 MSW 假 API 取代，**不需要後端、不需要自己架站**。

## 快速開始

```bash
npm install
npm run dev        # 本機開發
npm test           # 授權引擎單元測試
npm run build      # 產生靜態檔 dist/
```

## 讓夥伴直接點開看（不自己架站）

`dist/` 是純靜態檔案（使用 HashRouter、相對路徑），可放到任何靜態託管：GitHub Pages、Cloudflare Pages、Netlify、Azure Static Web Apps。
建議設定「每個 Pull Request 自動產生預覽網址」，夥伴點連結即可檢視。

## 內容

- 模擬登入（選示範帳號；正式登入方式尚未決定，暫不沿用 Keycloak）、多身分切換、依權限顯示的模組首頁與側邊選單。
- 學生資料示範「資料範圍」：清單由（假）後端依角色、範圍、教育階段、責任關係過濾。
- 帳號規則：登入帳號限英文字母、數字、_、-，且以英文字母開頭；「使用者姓名」另立欄位。學校管理員只能瀏覽本校使用者並指派學校層級角色（後端依資料範圍過濾與檢查）。
- 沒有獨立的「學校帳號」：帳號只有一種；一個帳號可在多個機構各有一個身分（帳號管理 › 新增身分），每個身分可指派多個角色，同一角色也可指派到不同機構。示範帳號 `multi_teacher`。
- 教育雲端登入一定帶學校代碼，登入時同步任職機構：首次登入的新使用者建立該校身分且不指派角色（示範 `sso_new_teacher`）；學校代碼與系統記錄不同時，清空原學校的角色並離任、改任新學校且無角色（示範 `sso_moved_teacher`）；調職、退休、離職由管理員在帳號管理按「調職／退休／離職」，同樣清空該機構角色。縣市、署的身分不受影響，全部寫入稽核。
- 治理畫面：帳號與角色指派、角色 × 模組 × 動作矩陣、範圍樹（分區 = 多個行政區／鄉鎮）、授權稽核紀錄。
- 家長、學生登入不納入第一階段。
- 帳號綁定身分證／居留證號：不論教育雲端帳號或本機帳號登入，缺少必填資料（身分證、聯絡方式）就只能進「個人資料」頁，後端所有授權請求也會一併拒絕（`PROFILE_INCOMPLETE`／`ID_PENDING`）。
  - 身分證只存雜湊與遮罩；教育雲端有 guid 時比對一致才自動驗證，其餘由範圍內管理員在「身分證核對」核准；與其他帳號相同者不可直接核准，也不會告知使用者。
  - 聯絡方式（電子郵件／手機／市話）用驗證碼驗證，市話無法驗證；示範驗證碼固定為 123456。
  - 國教署管理員在「帳號資料欄位設定」決定：身分證是否必填、可填哪些聯絡方式與最少項數、是否驗證聯絡方式、是否驗證身分證（關閉＝訓練站虛擬資料可直接通過）。儲存前會檢查設定可被滿足，且不會把操作者自己鎖在系統外。
  - 登入頁可選「教育雲端帳號（模擬）」或「本機帳號（模擬）」；許新進（有 guid）與謝署轄（無 guid）兩個示範帳號用來走補資料流程。
- 權限模擬：詢問後端「目前身分能不能做某件事」，並顯示拒絕原因。
- 教育輔具模組不保留，13 個模組中不含該功能。

## 結構

```
src/auth/engine.ts      授權引擎（純函式）與單元測試
src/mock/               假資料、假後端（MSW handlers）
src/api/client.ts       所有後端呼叫的唯一出口
src/auth/AuthContext    「我的權限」與身分切換
src/pages, src/layout   畫面
```

## 之後接真實後端

1. 設 `VITE_USE_MOCK=false`，MSW 不再啟動。
2. 只需修改 `src/api/client.ts`（網址、登入憑證標頭）。
3. 後端提供與 `MePermissions`（見 `src/types.ts`）相同格式的「我的權限」介面，並在每個 API 重新執行授權檢查。前端的隱藏與停用只是體驗，不是安全邊界。

## 限制

- 示範權限矩陣、角色與範圍都是**示範值，待業務核准**。
- 角色切換不是正式授權；資料全為合成資料。
- 學生清單以外的功能畫面目前是「功能掛載點」。
